# 首版取舍与后续决策

## 已落实

- 独立本地目录、Node22 ESM、零运行时 npm 依赖；界面和本地服务共源，仅监听127.0.0.1。
- 单聊与群聊采用同一消息模型，群聊按成员顺序各答一次，支持有边界的@提及，避免群成员无限互相触发。
- 会话历史在本机管理；ChatGPT使用公开Responses端点、store:false、stream:true，不使用私有backend-api或订阅Cookie。
- OAuth为用户主动操作；默认内存，持久化/恢复各自明确确认。只使用本应用注册，拒绝静默复用Codex身份。
- Provider与执行桥分开。普通聊天没有电脑权限；任务有独立确认和事件轨迹。
- 本地文件路径已经独立实现：专用目录列出/读取/新建文本，每步单次审批，拒绝路径逃逸和覆盖；无模型也能使用。
- 模型文件助手仅可使用相同三种工具；已完成假传输测试，真实模型尚未验收。
- 旧Codex桥RPC形态不匹配时在取得令牌之前失败关闭；命名权限配置单独以fixture验证，不把字段缺失推断为CLI能力缺失。

## 用户下一步可决定

1. 是否现在亲自完成官方登录，并允许一次短文本真实聊天验收；是否需要在本应用钥匙串持久保存登录。
2. 若三种文件动作仍不够，明确下一种实际工作需求后，再扩展受限工具或接入经过验证的Codex命名权限策略。当前没有授权任意shell；单纯升级CLI不是已核实的解决方案。
3. 首个远程电脑的具体系统、连接方式、授权目录和可执行动作。接入前需要可撤销配对、经认证传输、最小权限、审计及关键操作确认。
4. Android首版优先用于通知/审批，还是授权后的设备动作。设备拥有权、系统支持与Accessibility等权限需逐项确认；不为未授权设备建立控制通道。

## 尚未覆盖

桌面打包签名、多设备同步、多人账号隔离、真实手机控制、MCP配置界面、文件附件、语音与视频。现阶段应在个人本机使用，不公开部署此本地服务。
